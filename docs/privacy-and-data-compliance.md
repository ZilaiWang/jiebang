# 用户隐私与数据合规说明

## 1. 适用范围

本项目默认使用合成或脱敏学习数据进行开发、测试和演示。若接入真实培训、测试或学情数据，部署方应在适用法律法规、隐私政策、授权范围和数据处理协议允许的范围内使用，并承担相应的数据控制与处理责任。

## 2. 数据分类与处理

| 数据类别 | 示例 | 模型是否接收 | 默认处理 |
|---|---|---:|---|
| 直接身份信息 | 姓名、学校、手机号、邮箱、学号、工号 | 否 | 不进入模型；进入持久化前移除或脱敏 |
| 学习画像 | 等级、学习目标、已知/薄弱知识点 | 是，仅限当前教学需要 | 使用结构化最小字段 |
| 交互与测评 | 诊断答案、评分、掌握度、下一轮动作 | 仅在当前任务需要时 | 以匿名学习者 ID 关联；不写入普通日志 |
| 运行元数据 | 匿名 ID、会话 ID、时间、状态、错误码 | 必要时 | 用于会话恢复、审计和故障排查 |

## 3. 模型输入边界

Role C 和模型调用使用白名单投影，不传递姓名、联系方式、学校、学号、完整自然语言画像或不相关原始交互记录。讲义个性化只使用：

- 匿名学习者 ID；
- 当前学习等级；
- 学习目标和主目标类型；
- 已知知识点与薄弱知识点；
- 当前任务所需的结构化教学偏好。

事实、学习目标、正确答案、评分规则和安全边界不因脱敏或个性化而改变。

## 4. 持久化与保留

- 会话写入前清洗邮箱、手机号、身份证/学号类长数字；
- 嵌套画像中的 `name`、`school`、`phone`、`email`、`student_id`、`employee_id` 等直接身份字段会被移除；
- 本地持久化目录使用受限权限和原子写入；
- `session_only` 数据不应作为长期画像使用；部署方应根据保留期限清理原始答案、原始代码和临时上下文；
- 长期画像只保留个性化所需的结构化学习摘要。

## 5. 用户删除

当前主 Agent 提供：

```http
DELETE /orchestrator/privacy/learner-data
Authorization: Bearer <当前学习者身份>
```

接口只允许本机回环调用，并以认证身份为删除依据，不接受用户指定其他学习者。删除范围包括会话、学习记忆、路径、Role C 运行数据、生成检查点、学习循环数据和集中式掌握度快照中的对应条目。

## 6. 日志与安全红线

普通日志和公开会话不得包含：

- 姓名、手机号、邮箱、学校和学号；
- 原始画像长文本；
- 原始诊断答案、隐藏答案和完整代码；
- API Key、访问令牌、密码或连接字符串。

API Key 只用于本机模型配置，不写入学习记录或公开响应。

## 7. 责任边界

本说明描述的是项目实现的技术保护措施，不等同于针对具体地区、机构或业务场景的法律意见。正式上线前仍需完成适用法律评估、隐私告知、授权记录、数据保留期限、跨境传输和第三方模型服务条款审查。
