# 角色1 Day3 工作报告

1. 主流程加入审核阶段：完成。现在 C 生成讲义、代码实验、测评后，不是直接给前端看，会先进入"审核中"状态。

2. 审核通过后才能发布或展示：完成。没过审时，前端拿不到讲义、代码实验、正式测评。只有审核通过后，内容才会进入 learning_resources 和 assessment。

3. 审核失败后进入修复流程。审核失败后会记录失败原因，系统会保留失败的是哪个 worker（比如 code-lab），然后走原来的 retry/recovery 修复机制。

4. 修复后重新审核。修复后不会直接发布，会重新走 Role C 的 reviewed pipeline，即修完还要再检查一遍。

5. 多次失败后进入降级或 blocked。多次审核/修复失败后会进入 blocked，比如隐藏测试泄露、修复无进展这类问题，会被挡住，不会硬发给用户。

6. session 中能看到审核状态。session 里新增了 content_review，能看到：当前是审核中、修复中、通过、失败还是 blocked；哪个 worker 出问题；修了几次；是否允许发布。前端也加了"内容审核 · 发布门禁"卡片。

7. 前端显示审核状态。学习方案页会显示审核状态，如果审核没通过，会提示：审核未通过前，不展示 C 的讲义、代码实验或正式测评。
