# KnowBalance 1 周冲刺验收清单（weekly-acceptance-checklist）

> 生成：第0天（2026-08-11） · 4号·样例评测与前端体验负责人
> 用途：每天 22:30 汇报与第7天证据固化时逐项勾选；全部打勾 = 围绕四个评分项的高分作品。
> 依据：《一周计划》《四人分工计划》+ 当前 jiebang 仓库真实能力。

## 评分项 → 验收标准对照

| 评分项 | 验收标准 | 对应文档 |
|---|---|---|
| 作品完整性 | 系统闭环跑通：学习者输入→诊断→画像→路径→RAG→资源→审核→测评→反馈→决策 | docs/team_integration_guide.md |
| 技术创新性 | OpenCode 风格多 Agent 调度、防幻觉、动态决策 | docs/orchestrator_runtime_design.md、docs/fact_audit_api.md |
| 用户体验 | 流程清晰、状态可视、资源好读 | docs/role_d_frontend_guide.md |
| 实用价值 | 多组样例、量化指标、可迁移 | 本清单 day5 部分 |

## Day 2 · OpenCode 风格多 Agent 调度证据

- [ ] 主 Agent（learning-orchestrator）调度多个子 Agent 可见
- [ ] 每个子 Agent 有结构化输出（envelope）
- [ ] trace ledger 记录调用顺序和产物引用
- [ ] 证明主 Agent 是调度者不是直接生成者
- [ ] 验收：从评委角度能看懂 ledger（D 负责可读性检查）

## Day 3 · 防幻觉、审核、修复、降级

- [ ] 生成内容绑定 source_id / fact_id 引用
- [ ] 审核 Agent 能发现至少一种问题（缺引用/引用不支持/难度过高）
- [ ] 审核失败后触发修复
- [ ] 两轮失败后触发动态降级
- [ ] 验收：输出防幻觉审核报告

## Day 4 · 动态诊断、画像反填、动态决策

- [ ] 诊断结果反填画像（答对→known，答错→weak，冲突→记录）
- [ ] 路径根据画像动态变化
- [ ] 测评后四类决策：补救 / 巩固 / 进阶 / 重画像
- [ ] 至少两个学习者走出不同路径
- [ ] 下一轮生成资源能看出变化

## Day 5 · 三组样例 + 量化指标

- [ ] 三组学习者（零基础/薄弱/项目目标）全部完整跑通
- [ ] 幻觉率 < 5%
- [ ] 难度适配准确率 ≥ 85%
- [ ] 核心知识点覆盖率 ≥ 90%
- [ ] 验收：实用价值评测报告（D 负责）

## Day 6 · 用户体验与可解释性

- [ ] 前端展示 Agent 状态（当前/已完成/失败重试）
- [ ] 展示画像（已掌握/薄弱/目标/依据/冲突）
- [ ] 展示路径（当前节点/为什么先学它/前置后续/补救节点）
- [ ] 资源页：讲义重点小结、代码实验任务清晰、测评题型区分、引用可查看、错题解释原因
- [ ] 至少一个学习者能通过前端完成主要流程，用户不觉得是黑盒

## Day 7 · 最终整合、验收、证据固化

- [ ] 至少三组学习者从头完整跑通
- [ ] 完整检查通过：typecheck / 单测 / 前端验证 / 多Agent调度测试 / 指标脚本 / Docker 检查
- [ ] 完整证据包：运行样例、三组输入输出、ledger、画像、路径、引用、讲义、实验、测评、审核报告、指标报告、部署说明、测试结果
- [ ] 评分响应说明：四条评分项各对应哪些功能与证据文件
- [ ] 文档通俗易懂（D 负责最终文档验收）
