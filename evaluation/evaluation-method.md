# 正式评测方法

## 评测对象

主指标集固定为 60 个案例，覆盖三类学习者画像、K001–K018 单知识点任务和 6 个综合任务。每个案例均通过 Role D 所使用的主 Agent 服务生成讲义、代码实验和分阶测评，因此难度评测对象共 180 份资源。

辅助鲁棒性集固定为 12 例，验证幻觉诱导、证据异常、动态反馈和工程恢复。辅助集不进入三项主指标的分子或分母。

## 冻结内容

正式运行记录并哈希以下内容：代码提交、源码树、生成模型配置、独立评审模型配置、提示词版本、知识库版本、60 例 manifest 和难度 rubric。生成模型看不到期望难度；独立评审模型也看不到标准答案。

`manifest.v1.json` 中的 `required_fact_ids` 是课程核心事实，不等于知识库中可供生成使用的全部扩展事实。核心事实进入覆盖率分母；扩展事实仍可作为示例、边界说明或任务能力证据。

`manifest-review-template.csv` 用于两名成员在正式运行前独立核查 180 个资源期望。复核结论不回传给生成模型或独立难度评审模型。

## 指标定义

### 大模型内容幻觉率

从三类公开资源提取原子事实声明，再由独立模型逐条判定。`unsupported`、`contradicted`、`missing_citation`、`external_knowledge`、`semantic_unsupported` 和 `uncertain` 均计为问题声明。

```text
问题声明数 / 已审核事实声明数 < 5%
```

同时要求声明审核覆盖率不低于 95%，避免通过漏审缩小分母。

### 画像—资源难度适配准确率

期望难度在生成前按目标级画像状态、可观察行为、目标组合和综合项目属性确定。总体等级不会覆盖“已掌握/薄弱/未观察”的目标级证据。独立模型只看实际资源，按 `difficulty-rubric.v1.md` 精确分类。

```text
预测难度与冻结期望完全一致的资源数 / 已评审资源数 ≥ 85%
```

同时要求 180 份资源的难度审核完整度为 100%。

### 课程核心知识点覆盖率

只有公开内容真实表达核心事实、有有效引用且独立事实审核判为 `supported` 时，该事实才算覆盖。按“案例 + 事实”计数，不跨案例去重。

```text
被支持的案例—核心事实单元 / 冻结案例—核心事实单元 ≥ 90%
```

## 执行流程

1. 开发集：按三个画像各抽取 K001、K007、K013、K018，共 12 例，修复评测协议或明确的生产缺陷。
2. 正式集：60 例分别运行两次；标准冻结后不根据结果改单例答案。
3. 独立评审：声明审核与难度分类使用不同于生成模型的模型配置。
4. 可信执行：每个已发布代码实验读取真实 Docker 验证状态，不能用 `ready` 推断执行成功。
5. 人工复核：从三种画像和三类资源中分层抽取 12 个案例，由两名成员独立复核；争议项共同裁决。
6. 报告：保存逐声明审核、逐资源难度、案例输出、模型用量、协议哈希、分子分母及 Markdown 汇总。

## 运行命令

```bash
# 12 例开发检查
bun run eval:competition:dev

# 60 例 × 2 次正式评测
bun run eval:competition:final

# 12 例辅助鲁棒性检查
bun run eval:competition:robustness
```

正式评测需要显式配置生成模型和独立评审模型，且两者配置哈希不得相同。API Key 仅从本地环境变量读取，不写入评测产物。
